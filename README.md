# CLI Journal

Многопоточное консольное приложение и динамическая библиотека на C++17 для асинхронного логирования текстовых сообщений. 

Проект разработан для потокобезопасной записи сообщений в журнал (текстовый файл) с поддержкой различных уровней важности. Взаимодействие с библиотекой осуществляется через CLI-интерфейс, который выносит процесс записи на фоновый поток, предотвращая блокировку основного приложения.

## Архитектура
   В основе архитектуры лежат три класса:
   # class AsyncLogger (a.k.a. logger)
   * Данный класс отвечает только за работу с файлом. за основу взят std::shared_mutex, благодаря которому реализован паттерн множество читателей и один писатель. операции записи складываются в потокобезопасную очередь, откуда поток записи берёт задания. 
   # class LogManager  (a.k.a. manager)
   * Как видно из названия, данный класс представляет собой "прослойку" между приложением и логгером. именно этот класс решает, в каком виде будут лежать данные на диске(в файле), как они организуются и читаются с диска, обеспечивает целостность записей журнала.
   # class Application (a.k.a. приложение)
   * Наконец, приложение отвечает за работу с пользователем и передачу данных менеджеру. также решает, в каком виде показывать данные пользователю. 
---
   * в начале диска лежит HeaderMap размером 40 байт -- это карта состояния записей, которая при запуске приложения загружается в оперативную память.

   * Каждая из записей относится к одному из 5 уровней важности: Destroy, Delete, Low, Medium, High. Первые два вы не сможете ни вписать новым логом, ни задать "по умолчанию". данные два уровня системные. при удалении сообщения оно помечается Delete(планировалось, что такие сообщения в дальнейшем можно будет "восстановить"). записи с меткой Destroy восстановить уже не получится. 
   * также установлен минимальый уровень важности. если поступившее сообщение меньше установленного уровня -- оно игнорируется.   
   * также каждая "живая" запись находится в двусвязном списке. каждая "удалённая" или "уничтоженная" запись лежит в своём односвязном списке(связи лежат на диске, поэтому перезагрузка приложения не страшна).

   * при "уничтожении" память освобождается -- точнее, открывается возможность написать новую запись поверх уничтоженной прямо посреди файла, если размер нового сообщения не превосходит размера своего предшественника.  
   * при отрисовке реализован "метод скользящего окна". размер окна по умолчанию 5. данное окно можно "перемещать" командами, благодаря чему можно смотреть логи.

## Особенности архитектуры
* **Кэш**: при отрисовке "живых" сохраняется в оперативной памяти количество записей, равное размеру окну, и несколько рядом с обеих сторон, что позволяет лишний раз не обращаться к диску при просмотре записей.
* **Экономия памяти**: из-за того, что можно уничтожать записи и  перетирать их прямо в середине файла, мы по максимому используем память!
* **быстрая загрузка**: благодаря карте, что лежит по статическому адресу, можно не читать весь файл, чтобы найти свободное место или считать первые/последние логи -- достаточно считать карту!
* **быстрое чтение**: из-за того, что записи связаны в список, можно не читать всё сообщение целиком(чтобы узнать, где следующаяя запись), а достаточно считать системную информацию в заголовке и узнать адрес следующей записи! 
* **Асинхронность**: Основной поток приложения отвечает исключительно за чтение пользовательского ввода. Сообщения складываются в потокобезопасную очередь и обрабатываются фоновым потоком.
* **Динамическая загрузка библиотек**: классы `AsyncLogger` и `LogManager` спроектированы так, что каждый из них компилируется в свою динамическую библиотеку. другими словами, если вам не нравится, как реализована работа с диском(файлом), вы можете написать свой класс, собрать в дин.библиотеку и подключить, не переделывая остальной код! аналогично и с менеджером.

## Требования
* ОС: `Ubuntu / Debian`
* Компилятор: `GCC` с поддержкой `C++17`
* Утилиты: `make`

## Сборка проекта
Используется Makefile для удобного управления процессом сборки.

1. **Собрать всё (библиотеки и приложение):**
   ```bash
   make all
   ```
2. **Собрать библиотеку Logger-а:**
   ```bash
   make logger_lib
   ```
3. **Собрать библиотеку Manager-а:**
   ```bash
   make manager_lib
   ```
4. **Запустить тесты:**
   ```bash
   make test
   ```
5. **Очистить директорию от бинарных файлов (clean):**
   ```bash
   make clean
   ```
Скомпилированные файлы появятся в директории `bin/`.

## Использование

Для запуска приложения необходимо передать два обязательных аргумента: путь к файлу журнала и уровень важности по умолчанию (LOW, MEDIUM, HIGH).
```bash
./bin/journal_app <путь_к_файлу> <уровень_важности>
```

Пример запуска:
```bash
./bin/journal_app app_logs.txt MEDIUM
```

### Команды CLI (Интерфейс)

После запуска приложения вы попадете в интерактивную консоль `>`. Поддерживаются следующие команды:

* `help` - Вывести список доступных команд.
* `exit` - Завершить работу приложения.
* `log` - Вывести всё содержимое текущего журнала в консоль.
* `stp <count>` - Сместить окно вперёд(если count > 0), или назад(count < 0).
* `del <index>` - Пометить сообщение как удалённое (индекс вычисляется относительно окна).
* `dst <index>` - Уничтожить сообщение и освободить место (индекс вычисляется относительно окна).
* `jnl -gl` - Вывести текущую важность по умолчанию.
* `jnl -sl <level>` - Изменить важность по умолчанию на указанный уровень.
* `msg [level] <text>` - Сохранить сообщение в журнал с указанным уровнем важности. Если уровень не указан, используется настройка по умолчанию. Текст можно оборачивать в кавычки.
* `<text>` - Любой ввод, не являющийся командой, интерпретируется как сообщение с уровнем важности по умолчанию.

сообщения выводятся на экран в виде(где `index` -- индекс относительно окна, `date` -- дата и время записи лога, `level` -- уровень важности):
```
=== [ index ] ===
[date] [level]
text
```
